\section{Experiment framework}
\label{sec:framework}

One experiment is one YAML file. A configuration file inherits from a global
default file, a dataset file and an extractor file through a \texttt{defaults}
list, and the resulting document is hashed; that hash names both the cache
directory of every expensive artefact and the directory of the run. Datasets,
extractors, graph builders, relevance functions and evaluators are registered
under a name, so adding a model means adding one class and one configuration
file rather than editing the pipeline.

Every execution writes a directory holding the resolved configuration, the
metrics, the figures, the log, and a provenance record with the git commit,
whether the working tree was clean, the exact version of every dependency, the
seed, the platform and the time each stage took. A number in this report can
therefore be traced back to the code and the configuration that produced it.

\section{The CNN classifier and MERT}
\label{sec:trained-models}

MERT-v1-95M \cite{Li2023} is a frozen, pre-trained transformer: a 12-layer,
768-dimensional HuBERT-style encoder trained on 24\,kHz music audio with
masked-language-model pre-training. A forward pass exposes 13 hidden states
(the convolutional feature extractor's output, plus the 12 transformer
layers); each is mean-pooled over time, and the resulting
13\,$\times$\,768 array is cached per track (\texttt{musicsim/extractors/mert.py}).
Because the model was pre-trained on 5\,s crops rather than 30\,s clips, every
track is processed as six non-overlapping 5\,s windows instead of one 30\,s
forward pass -- quadratic self-attention over a 6$\times$ longer sequence
would cost roughly 36$\times$ more for the same audio -- and the six windows'
pooled vectors are themselves averaged. This is the same "several short crops,
then averaged" strategy the CNN classifier below uses at 3\,s.

Layer selection is model selection, so it happens on FMA \emph{validation}
only, never on test: each of the 13 layers is L2-normalised (no
standardisation, so every layer is compared under the same conditions) and
ranked by Recall@10 on the validation split
(\texttt{musicsim.extractors.mert.select\_titular\_layer}); the winning layer
is the one every later stage uses, and all 13 stay available only as the
material for a per-layer figure (\todo{figure: R@10 against layer index, 0-12}).
On the 800-item FMA validation gallery, layer \textbf{6} (of 0--12, i.e. the
6th transformer layer) gives the highest Recall@10, \textbf{0.0548}, against a
roughly unimodal curve over the 13 layers (0.0411--0.0548, lowest at the
input-adjacent layer 12 and the convolutional-feature layer 0, highest around
the middle of the stack) -- consistent with self-supervised speech/music
encoders generally carrying the most task-general information in their middle
layers rather than their first or last. Extraction is CPU-viable but
expensive: \textbf{$\approx$4.0\,s/track} measured on an 8-core CPU (six 5\,s
forward passes per 30\,s clip, single process -- see below), so the full
\texttt{fma\_small} corpus (7994 tracks) costs on the order of
\textbf{9 hours of CPU time}; the weights
(\texttt{m-a-p/MERT-v1-95M}, revision \texttt{12af15fe}) are downloaded from
Hugging Face into the user's own cache under \textbf{CC-BY-NC-4.0}, which
permits the non-commercial research use this thesis makes of them.

\section{Similarity graph}
\label{sec:graph}

\subsection{The canonical graph}
\label{sec:graph-canonical}

The canonical crisp graph is the directed $k$-nearest-neighbour graph by cosine
similarity with $k=10$. Embeddings are L2-normalised, so the similarity matrix
is a matrix product, computed by brute force in blocks of 512 rows: peak memory
is proportional to $512\times N$ and the full $N\times N$ matrix is never
stored. Self-exclusion is done by row index and not by comparing similarity
values; with duplicated vectors a value-based rule would remove the wrong
neighbour. A node $i$ stores its neighbours ordered by decreasing similarity,
with the similarity as the edge weight.

A graph is a pair of $N\times k$ arrays, so a node may have fewer than $k$
neighbours (mutual kNN, thresholds): the missing slots are filled with a
padding value, always at the end of the row, and are not edges. Every
structural quantity is computed from one sparse adjacency view of the graph
(\texttt{musicsim/graphs/adjacency.py}), so that all of them agree on what an
edge is: padding slots and self-loops are not edges, and a neighbour listed
twice counts once. The view is \emph{directed} ($i\to j$ if $j$ is among the
neighbours of $i$) or symmetrised. The symmetrisation by union ($i - j$ if
either direction exists) is the one used by community detection, clustering
and connectivity; hubness, homophily and reciprocity use the directed view.

\subsection{Which items are nodes}
\label{sec:graph-gallery}

A graph that is analysed is always built from the items of its own gallery,
never over the whole corpus and cropped afterwards. Cropping leaves nodes with
fewer than $k$ neighbours and changes the k-occurrence of those that remain, so
every structural figure would describe a graph nobody built. On \texttt{fma\_test}
the graph therefore has the 800 test tracks as candidate nodes, and no edge
leaves the split.

Near-duplicate groups are collapsed to a single node, the one with the smallest
item identifier, before the graph is built. Duplicates are detected on one
\emph{reference} representation (\texttt{mfcc}) with a cosine threshold of
0.9999, once per gallery, so that every representation's graph has exactly the
same nodes. Left in, each duplicate pair would be a trivial reciprocal edge that
inflates reciprocity and clustering. In \texttt{fma\_test} this removes 5 of the
800 tracks, leaving 795 nodes.

\subsection{Graph comparison and export}
\label{sec:graph-compare}

Two graphs over the same nodes, in the same order, are compared with four
statistics (\texttt{musicsim/graphs/compare.py}): the mean over nodes of the
Jaccard index of the two neighbour sets (the headline); the Jaccard index of the
two directed edge sets; the Spearman correlation of the two k-occurrences, that
is, whether the same nodes are hubs; and the adjusted Rand index between two
Louvain partitions. Comparing graphs with different identifiers is an error and
not something the code tries to align.

A graph is exported with its node attributes (identifier, genre, artist, split,
k-occurrence and community) as \texttt{nodes.csv} and \texttt{edges.csv}, and as
a directed GraphML file that opens in Gephi or Cytoscape
(\texttt{musicsim/graphs/export.py}). A missing attribute is omitted from the
GraphML node, because that format cannot store a missing value and an empty
string would be indistinguishable from a real label.
